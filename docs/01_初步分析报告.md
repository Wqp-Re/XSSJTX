## 2. 关键技术结论

### 2.1 引擎与版本
| 项 | 值 |
|---|---|
| 引擎 | Cocos2d-x JSB（JS / TypeScript 风格，Cocos Creator 2.x） |
| Cocos Creator 版本 | **2.4.7**（来自 `assets/project.json` 的 `engineVersion` 字段） |
| 语言 | JavaScript（非 TypeScript，不需要编译为字节码外的预处理） |
| 平台 | Android only（iOS 资源未打包，符合纯安卓玩法） |
| 包名 | 通过 `AndroidManifest.xml` 可读取（解包后是二进制 AXML，需 aapt2 工具解析） |
| 体积 | APK 33 MB，其中 `assets/native/` PNG 等图资源占大头 |
| 加密 | 全 JavaScript 模块用 **XXTEA + gzip** 双层加密 |

### 2.2 核心加密方案
所有 `.jsc` 文件遵循：Cocos Creator 2.4.7 标准方案：
```
encrypted_jsc = XXTEA_encrypt( gzip(js源代码), key[, sign] )
```
其中：
- `key` 是 16 字节主密钥，**作者通过构建面板设置**
- `sign` 是 n 字节签名（默认 2，常见 16）
- 解密在 native 层 `jsb.fileUtils.setXXTEAKeyAndSign()` 中

### 2.3 加密文件分布（业务核心）
| 文件 | 大小 | 估计内容 |
|---|---|---|
| `assets/src/settings.d3c33.jsc` | 340 B | 构建配置 + xxtea key 存放地（被自身加密） |
| `assets/assets/main/index.ae18c.jsc` | **617 KB** | **主游戏逻辑**（场景脚本、玩家行为、数据表） |
| `assets/assets/resources/index.56145.jsc` | 1.7 MB | 资源 bundle 加载逻辑 |
| `assets/assets/internal/index.60559.jsc` | 3.0 KB | 引擎初始化 |
| `assets/src/cocos2d-jsb.ae331.jsc` | 1.8 MB | Cocos 引擎运行时（标准模板） |

> 解开 **617 KB 的 main/index.XXX.jsc 等同于"掌握整个游戏的所有玩法代码与数据表"**。

## 3. 反编译过程中遇到的卡点

### 卡点 A：XXTEA 密钥不在 libcocos2djs.so 明文区
我已用 Python 在 `libcocos2djs.so` 的全部 ASCII 字符串中检索 `xxtea/XXTEA/cipherkey/setxxtea/UUID`，**未找到任何硬编码的 key 候选**。这是因为本项目的 key 是构建时由游戏作者在 Cocos Creator 项目里设置的独立字符串，没写进 native 层。

### 卡点 B：明文 JS / JSON 中没有 setXXTEA 调用
- `assets/main.js`（启动模板）：是 Cocos 官方模板，未调用 `setXXTEAKeyAndSign`
- `jsb-adapter/jsb-builtin.js`、`jsb-adapter/jsb-engine.js`（引擎适配层，464 KB 全文）：不出现 xxtea
- 全部 `import/` 下的 3350 个 JSON 资源：不出现 xxtea
- **因此 key 只能存在于加密的 settings.jsc 自身**（自指加密）

### 卡点 C：settings.d3c33.jsc 仅 340 字节
加密算法不可逆，需要 16 字节主密钥才能解开。本项目作者用了一个非标准做法：**让 settings 自己也加密**。这意味着 key 来自 `cocos2d-jsb.ae331.jsc` 里的 `__settings.__private__.xxteaKey` 字段——递归死锁。

> 实战上，能解开 settings 的方法只有两条：
> 1. **作者提供 key**（最快）
> 2. **运行时 hook**（用 Frida 等工具在 APK 第一次 `setXXTEAKeyAndSign` 调用时 dump key+sign）

## 4. 如果拿到 key 后的完整解密 SOP（预备步骤）

下面准备好所有脚本，你得到 key 即可一键解密全工程：

### 4.1 准备 Node 环境
```bash
# 安装 Node.js 16+（Windows 自带 winget 或官网）
node -v
```

### 4.2 一键解密所有 jsc
```bash
cd workspace\scripts\jsc2js
node install.js  # 已带包；如果依赖未装执行：npm install

# 假设作者给了 key = "MySecretKey16___"
node index.js E:\Codebuddy\XSSJTX\workspace\apk_unzipped\assets -k "MySecretKey16___" -o E:\Codebuddy\XSSJTX\workspace\decrypted -r
```

将生成：
```
workspace\decrypted\
  src\settings.d3c33.js        (明文 settings，含 build uuid、场景列表)
  src\cocos2d-jsb.ae331.js     (引擎模板)
  assets\main\index.ae18c.js   (核心游戏脚本，含所有玩法/数据)
  assets\resources\index.*.js
  ...
```

### 4.3 解开后的扫读清单
拿到 .js 后，请重点关注：
- `assets/main/*.js` 中的字符串表（角色名、技能、装备词条、关卡名、怪物表）—— 一般以 `cfg_data` / `GameData` / `Localization` 等常量数组形式
- 网络相关常量（如果有）：`serverUrl`、`loginUrl`
- 关键函数：`onPlayerHpChange`、`onDrop`、`onBattleResult`、`onLevelComplete`

## 5. 不依赖解密也能做的"外围分析"清单

即便你还没拿到 key，以下可以**立刻**继续做（不需要解密任何 jsc）：

### 5.1 资源 metadata 分析（`import/` 下 .json）
几乎所有 Cocos Creator 资源都有 `import` 目录里的元 JSON（**不是**加密的）：
- 提取所有场景名（找 `scene` 类型节点）
- 提取所有预制体名（`prefab` 类型）
- 提取所有 PNG 资源名（用于理解图标体系）
- 提取所有 Spine / DragonBones / fbx 动画名
- 提取所有音乐 / 音效文件

### 5.2 资源本体分析（`native/`）
直接看 PNG/TGA/Atlas，结合 import JSON 中"`atlas`" 字段，能得到**UI 拼图配置**。这对重新设计界面至关重要。

### 5.3 资源依赖图重建
遍历 `import/*.json`，根据 `dependson`/`dependency` 字段重建资源关系图，理解核心玩法资源 —— 这就足以设计"换皮/换玩法"的程度。

### 5.4 Lua / JS 反混淆支持
解密后如果 jsc 解出来仍是混淆形态（变量名短、不可读），可以进一步：
- 安装 `npm i -g javascript-obfuscator-reverse` 或 `webcrack`
- 或者 `npm i -g js-beautify` + `prettier`

### 5.5 重新打包签名
APK 重新签名需要：
- `apktool.jar` + `uber-apk-signer.jar`（Windows 自带 Java 即可）
- 项目里写一份 `ApkSigner/AutoSign.md` 流程（我等会儿生成）
